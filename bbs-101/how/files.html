BBS 101 / How a BBS Works

Files

Before the web had “download,” boards had file areas: shelves with names, descriptions, and a protocol that crawled across a phone line while you stared at a progress bar like it was television.

A file base is grouped by topic — ANSI packs, utilities, text, music, whatever the sysop bothers to keep. Each file has a name that looks like it survived DOS, and a description written by a human who may or may not have been tired. Read the description. That is the whole catalog.

Uploads are manners

Taking files and never putting anything back was a high crime on busy 90s boards, enforced with ratios. Many telnet boards are gentler now. The ethic is the same: if you have something good and allowed, offer it. If you do not, write messages instead. Bandwidth is cheap. Attention is not, and empty leeching still reads as empty.

Protocols, briefly

ZModem, XModem, YModem, and later extras like scp/sftp on SSH boards — these are just how the bytes move. Your client usually picks. SyncTERM and NetRunner will handle it. You do not need to romanticize the protocol. You need a working one.

What belongs here

Stuff the sysop wants on the board. That sounds tautological because it is. Warez culture is a historical fact of BBSes; it is not an invitation. If you are unsure whether a file should be uploaded, it should not. Ask, or don’t.

Then go back to the message bases. The files will wait. They are patient. They are bones.
